# **Data Dictionary & Business Mapping**

## **Objective**

Create a data dictionary that converts technical column names into clear business meanings.

The documentation should help analysts understand:

- What each column represents
- Which KPI it supports
- How columns relate to each other
- Which column names are ambiguous
- What assumptions or constraints apply to each field

The data dictionary will act as the team's **single source of truth** for understanding the dataset.

Task 3 — Identify Ambiguous Columns

Identify columns whose names could be misunderstood.

Create a section such as:

## Ambiguous Columns & Resolutions

### flag_churn

- **Original Ambiguity**: Does it represent current churn or future churn?
- **Resolved Meaning**: Indicates whether the customer churned within 90 days.
- **Business Interpretation**: Historical churn indicator.
- **Proposed Rename**: has_churned_90d
- **Risk**: Misinterpreting the field could produce incorrect retention analysis.

### cust_segment

- **Original Ambiguity**: Could refer to customer, product, or geographic segment.
- **Resolved Meaning**: Customer market segment.
- **Business Interpretation**: Used to compare customer groups.
- **Proposed Rename**: customer_segment
- **Risk**: Incorrect grouping could lead to misleading business conclusions.

Identify at least 2 ambiguous columns.

Task 5 — Create Markdown Data Dictionary

Create:

docs/DATA_DICTIONARY.md

Use a structured format:

# Data Dictionary

## Dataset Overview

This dataset contains customer transaction records used for business and customer analysis.

- **Update Frequency**: Daily
- **Maintained By**: Data Engineering Team

## Columns

### customer_id

- **Type**: Integer
- **Business Meaning**: Unique customer identifier from the CRM.
- **Example**: 12456
- **Null Handling**: Should never be null.
- **Related KPI**: Customer count, customer lifetime value
- **Updates**: Created when a customer is added to the CRM.

### trnx_amt

- **Type**: Float
- **Business Meaning**: Revenue generated by a transaction.
- **Example**: 150.99
- **Unit**: USD
- **Null Handling**: Investigate missing values.
- **Related KPI**: Monthly revenue, average transaction value
- **Updates**: Recorded when a transaction is completed.

### cust_segment

- **Type**: String
- **Business Meaning**: Customer market segment.
- **Valid Values**: B2B, B2C, SMB
- **Example**: B2B
- **Null Handling**: Use `UNKNOWN` when necessary.
- **Related KPI**: Segment revenue, segment churn
- **Updates**: Updated monthly.
